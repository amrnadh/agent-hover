Getting started

Agent Hover docs

Agent Hover sits on your running React app in development. You point at an element, say what should change, and your coding agent gets the exact file, the line that renders it, how it looks now and what it must not touch.

It has two halves. Asking: point, describe, send. Reviewing: the task stays on the element while the agent works, and when it's done you compare, keep, undo or follow up, right where the change happened.

Point→Ask→Agent works→Review→Keep or Undo

It works with Claude Code, Cursor, Codex, OpenCode, Windsurf, Antigravity, Claude Desktop and any other MCP agent. For chat tools like ChatGPT, Claude.ai, v0, Lovable and Bolt, Copy gives you a self-contained prompt.

Getting started

Install with init

In your Vite + React project, run:

Terminal
npx agent-hover init

init does four things, and shows every change and asks before writing anything:

  1. Installs @agent-hover/vite (or @agent-hover/next in a Next.js app) as a dev dependency, with your package manager.
  2. Adds it to your app: the plugin in your Vite config, or in Next.js, withAgentHover() in next.config, a call in instrumentation.ts and <AgentHover /> in your root layout.
  3. Connects your agents. Pick them from a checklist (↑ ↓, space, a for all, Enter). The ones your project already uses are ticked, and each shows where its config goes. It writes the MCP config, a short rules note, and an /agent-hover command for each one.
  4. Keeps local data out of git by adding .agent-hover/ to .gitignore.

--dry-run only shows the plan. In scripts and CI, where there's no terminal to ask in, use --agent and --yes. Esc or Ctrl+C cancels at any point.

Windsurf and Antigravity keep their config in your home folder, so init writes those globally, after showing them in the plan and asking.

Getting started

Your first task

  1. Start your dev server (npm run dev) and open the app. The dock appears at the bottom of the page.
  2. Press Alt, or the pointer in the dock, and click anything.
  3. Press Ask, type what to change, and press ⌘ Enter (Ctrl Enter on Windows and Linux).
  4. In your agent, run /agent-hover ($agent-hover in Codex), or tell it “Listen for agent-hover tasks.” It picks up each task you send, does it, reports back and waits for the next one.

/agent-hover-status lists what's waiting and running without starting anything.

Something not working? npx agent-hover doctor checks the plugin, the dev server, the token and the agent connection, and tells you what to fix.

Getting started

Manual setup

If you'd rather not run init, install the plugin yourself:

Terminal
npm install -D @agent-hover/vite
vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import agentHover from '@agent-hover/vite';

export default defineConfig({
  plugins: [react(), agentHover()],
});

Then register the MCP server with your agent. For Claude Code:

Terminal
claude mcp add agent-hover -- npx -y @agent-hover/mcp

npx agent-hover mcp <agent> prints the config for cursor, codex, opencode, windsurf, antigravity and claude-desktop.

Next.js

Terminal
npm install -D @agent-hover/next
next.config.ts
import { withAgentHover } from '@agent-hover/next';

export default withAgentHover(nextConfig);
instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs' && process.env.NODE_ENV === 'development') {
    await (await import('@agent-hover/next/register')).register();
  }
}
app/layout.tsx
import { AgentHover } from '@agent-hover/next/script';

<body>
  {children}
  <AgentHover />
</body>

With the Pages Router, put <AgentHover /> in pages/_document.tsx after <NextScript />, imported from @agent-hover/next/document. All three only do something under next dev.

Getting started

Requirements

  • Node 20 or newer, and React 18 or 19 with Vite 5 or newer (tested up to Vite 8), or Next.js 15 or newer with React 19 (App Router or Pages Router, Turbopack or webpack).
  • macOS, Linux and Windows 10/11.
  • Chrome, Edge, Firefox and Safari.
  • Dev only: it runs with vite dev or next dev and adds nothing to production builds.
  • Compare and Undo need a git repository. Everything else works without one.

Using it

The dock

The dock sits on your running app, in development only. It shows whether your agent is connected, starts everything else, and its Tasks dot tells you when something needs you.

  • Agent status: green when an agent is connected.
  • Inspect turns pointing on and off (same as Alt).
  • Comment, Tasks and Batch open their modes and tabs.
  • More holds the rest. A vertical dock is an option in Settings.

⌘ Shift X hides or shows the dock.

Using it

Point and select

Press Alt (or the pointer in the dock) and move over the page. A blue outline and a tag show what's under the pointer and where it's rendered. Click to select it.

The pill

A small pill appears above the selection with Ask, Comment, add to Batch and Copy. Under More: open in your editor, screenshot, lock from agents, parent and child, and details.

Cards and lists use plain names: “Book a demo” button, “Pricing” link, <StatCard />. The code name (button#hero-primary-cta) stays in the hover tag, in prompts and in the pill's tooltip.

Moving around

  • ↑ and ↓ select the parent or child.
  • Hold ⌘ (Ctrl) to show distances to nearby elements.
  • Hold Shift to click through to your page, for example to open a menu before selecting inside it.
  • O opens the element's file in your editor.

Exact file and line

On React 19, the element's own creation stack is mapped back through the dev server's source maps to the exact file and line, in Chrome, Firefox and Safari. An element drawn by a shared UI block (ui/button.tsx) points to where the block is used (<Button> in Hero.tsx), so the agent changes this usage rather than every button.

Using it

Ask

Press Ask or Enter on a selection. Describe the change in your own words (or click the mic and say it) and press ⌘ Enter.

  • Where it goes: to your connected agent. When none is connected, or when you prefer Copy, the prompt goes to the clipboard instead.
  • Picking an agent: with several connected, pick which one gets it. Only that agent receives the task. Comments and Batch go to the same agent. Two sessions of one agent show as one agent with a session count.
  • Not just styling: you can ask for what's missing, like “add an Export CSV button next to this header”.

Using it

Track

When you send, a marker appears on the element and follows the task:

Sent→Seen→Working→Done→Review
  • While the agent works, the card counts how long it has been at it.
  • Markers come back after a reload.
  • A marker whose element is covered (your own dialog, a sticky header) is hidden until it's visible again.
  • A task no agent picked up shows “Not picked up” and can be sent again. A failed one gets Try again. Both offer Copy prompt for any AI tool.

Using it

Review

A finished change that touched files waits on its element until you decide. The marker gets a ring, and the dock's Tasks dot stays on.

Keep K

Settles the change. The checkpoint stays, so Undo is still possible from Tasks until checkpoints are pruned.

Undo U

Restores exactly the files that changed, after showing you the list. When the agent picks up a task, Agent Hover takes a git checkpoint of your work tree, including uncommitted and untracked files, without touching them. Undo never runs git reset, clean or checkout: it restores the listed files one by one. Tasks that changed no files don't offer Undo.

Follow up F

Opens Ask on the same element. The new prompt carries a “Previous attempt” section with the earlier request, the agent's summary and its files, so the agent builds on the change instead of starting over.

Your decision is saved with the task, so it survives reloads.

Using it

Tasks

Press T or the Tasks button in the dock. Everything you've sent is sorted by what it needs from you:

  • Needs you: changes to review, and failures.
  • In progress: what agents are working on now.
  • History: folded by default, with Clear to remove everything with nothing left to decide.

Rows show the status and the exact file:line. ↑ ↓ move between rows, Enter opens one, Delete removes it. Keep and Undo work from here too. Finished tasks older than a week leave the list on their own; changes still waiting for review stay.

Using it

Comment

Press C to drop numbered notes anywhere on the page, or comment on the current selection. Use it for small things: a header that isn't aligned, an odd date format.

  • A pin sits at the element's top-left corner, outside it, clear of any task marker.
  • Send notes one at a time, or all at once as a single task.
  • The Comments tab lists them with the same numbers as the pins.

Using it

Batch

Some changes are about several elements at once: “make this tile match those cards”. Batch lets you point at all of them in one task.

  • Press B to add the selection, or click elements while the Batch tab is open (the cursor shows a +). Click again to take one out.
  • Mark each element Change, Reference or Don't touch.
  • Write the goal at the bottom of the sidebar and send.

Using it

Lock

“Don't let agents change this” on a component puts it in every prompt as off limits. That's the ask; Agent Hover also checks.

Using it

Inspect

The Inspect tab shows everything Agent Hover knows about the selection:

  • The component and a clickable breadcrumb up the tree.
  • Live props (secrets redacted), hooks and text.
  • The box model and key styles.
  • The source, with the token count of what would be sent.

Using it

Copy

⌘ C on a selection, or Copy in the pill, puts the full context on the clipboard. Every copied prompt is self-contained, so you can paste it into ChatGPT, Claude.ai, v0, Lovable, Bolt or anything else.

Using it

Voice

The mic in Ask and in new comments lets you speak instead of typing. While it listens, it turns red and glows, and an empty box says “Listening…”. Esc stops and keeps what was said.

It uses your browser's speech recognition, in your browser's language. It's hidden where the browser has none (Firefox). Settings › Voice turns it off. See Privacy for where audio goes.

What your agent receives

A short, ordered brief instead of a vague description. Real output for “Make this button larger with a subtle arrow icon”:

task.md
# Change request: <button> “Book a demo” in <Hero />

## What to do
Make this button larger with a subtle arrow icon

## Where
- Element: `button#hero-primary-cta` with text “Book a demo”
- Rendered by: `<Hero />` in `src/components/Hero.tsx`, lines 14–80
- In the source, the element is around line 55
- It is rendered through `<Button>` (line 54), a shared component: change this usage
  (className or props) rather than `<Button>` itself, unless the request is about every Button.

## The element now
- Rendered: 135×44px · font 14px/500 · color #ffffff on #17181a · padding 0px 24px · radius full

## Constraints
- Change this element only; keep the rest of <Hero /> as it is.
- Follow the existing styling approach (Tailwind utility classes in this file).

Troubleshooting

Start with doctor

npx agent-hover doctor checks the plugin, the dev server, the token and the agent connection, and says what to fix.

“Restart your dev server to finish updating”

After an update, the page loads the new Agent Hover right away, but the dev server keeps running the old one until it restarts. Restart it and the notice goes away.

The agent connects but gets 401

The MCP server looks for your dev server in its working folder, then in the workspace folders the agent reports, then in a list each running dev server keeps in ~/.agent-hover/bridges/. Make sure the dev server is running, then restart the agent. Set AGENT_HOVER_HOME to move that list.

A task says “Not picked up”

No agent was listening. Run /agent-hover in your agent, then use Send again on the task.

Reference

Privacy and security

  • Everything runs on your machine. The bridge listens on 127.0.0.1 only, checks the page's origin, and requires a per-session token, stored in .agent-hover/session.json, which init adds to .gitignore.
  • No telemetry. The only outbound request is a once-a-day update check to the npm registry, with no project data. Turn it off with AGENT_HOVER_NO_UPDATE_CHECK=1 or the usual NO_UPDATE_NOTIFIER=1.
  • Voice uses your browser's speech recognition: on the device when the browser can, otherwise Chrome and Edge send the audio to Google or Microsoft and Safari to Apple. You're told once, before the first use. Agent Hover never receives or stores audio.
  • Undo never runs git reset, clean or checkout.

Details: SECURITY.md and the bridge API.
